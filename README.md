# Image Cropper 人物圖片裁切器

使用 `isnet-anime` 人物辨識模型產生建議裁切框，並在靜態圖片的第一次結果不可靠時以 `birefnet-portrait` 進行二次辨識。逐張確認裁切範圍與輸出倍率後，將結果輸出至指定資料夾的 Windows 桌面工具。

程式不會移除背景；輸出時會先進行矩形裁切，再依 50%～200% 的倍率縮放裁切結果。

## Description 描述

程式會讀取 `input` 根目錄中的待處理圖片。PNG、JPEG 與靜態 WebP 會先依檔案建立時間由舊到新顯示，GIF 則排在所有靜態圖片之後，並在 GIF 組內維持相同排序。人物辨識會在背景執行，完成後產生建議裁切框。靜態圖片若第一次沒有有效裁切框，或未加留白的裁切框面積達全圖 95%，會自動使用精細人物模型重新辨識一次；兩次結果不會合併。使用者可移動裁切框，或拖曳四邊與四角調整範圍。

模型準備完成後，單一背景辨識工作者會依上述順序持續預先辨識所有剩餘圖片。使用者調整目前圖片時，後續圖片的建議裁切框會保存在記憶體中；切換下一張時若結果已完成即可直接使用。程式不會快取人物遮罩、完整圖片或 GIF 影格，也不會讓多張圖片同時呼叫 GPU 模型。

辨識完成後，使用者可選擇 50%～200% 的整數輸出倍率；每張圖片預設為 100%。介面會即時顯示輸出尺寸、來源檔案大小與預估輸出大小。確認後，程式會先裁切再縮放，以原檔名寫入 `output`，然後自動前往下一張。若無法可靠辨識人物，裁切框會預設為整張圖片，仍可手動調整。

## Supported File Types 支援格式

| 格式 | 副檔名 | 輸出方式 |
|---|---|---|
| PNG | `.png` | 無損輸出並保留透明度。 |
| JPEG | `.jpg`、`.jpeg` | 盡量沿用來源圖片的量化表與色度抽樣設定。 |
| WebP | `.webp` | 靜態 WebP 使用無損輸出；動畫 WebP 尚未支援。 |
| GIF | `.gif` | 保留完整影格、播放時間、循環、disposal 與透明效果。 |

靜態圖片會依 EXIF 方向資訊校正方向，並在可用時保留 ICC 色彩描述、DPI 與 EXIF 中繼資料。動畫 WebP 會列為未處理圖片；其他不支援格式及 `input` 的子資料夾會被忽略。

## Features 主要功能

1. 使用 `rembg` 的 `isnet-anime` 模型辨識動漫人物與 VTuber 角色。
2. 靜態圖片的第一次結果不可靠時，使用 `birefnet-portrait` 進行一次獨立的精細人物辨識。
3. 依遮罩亮度自動切換辨識門檻，兼顧暗場與近距離人物圖片。
4. 過濾過小、位於邊界或距離人物過遠的遮罩雜點。
5. 支援多個顯著人物區域，並在建議裁切框四周保留留白。
6. 可拖曳框內區域移動裁切框，或拖曳四邊及四角改變大小。
7. 裁切框外以半透明黑色遮罩顯示，方便預覽實際輸出範圍。
8. 逐張確認後立即輸出，遇到同名檔案時會先詢問是否覆寫。
9. 圖片讀取失敗時會略過；儲存失敗時保留目前裁切框與倍率，讓使用者修正或重試。
10. GIF 會從第 1 格開始每隔 5 格辨識一次，並額外辨識最後一格。
11. GIF 動畫預覽會依各影格時間持續循環播放，所有影格共用同一個裁切框。
12. GIF 先寫入暫存檔並完整驗證，成功後才取代正式輸出。
13. 使用 CUDA 環境，讓本機 GPU 加速所有支援格式的人物辨識。
14. 支援 50%～200% 的裁切後輸出倍率，使用高品質 LANCZOS 縮放。
15. 透明圖片採用透明度安全縮放，降低透明邊緣的黑邊與雜色。
16. 即時顯示輸出像素尺寸、來源大小及依像素比例計算的預估輸出大小。

## Requirements 系統需求

- Windows
- Python 3.11
- 首次下載辨識模型時需要網路連線
- 支援 CUDA 的本機 NVIDIA GPU，以及可用的 NVIDIA 驅動

Python 套件：

- Pillow
- NumPy
- rembg
- ONNX Runtime GPU（包含 CUDA、cuDNN 執行套件）
- SciPy

確切版本請參閱 `requirements-gpu.txt`。程式必須成功建立主要 CUDA session 才能開始處理圖片；不提供整張圖片的 CPU 辨識模式。ONNX Runtime 仍可在同一個 CUDA session 中，讓不支援的節點使用 `CPUExecutionProvider`。

## Getting Started 安裝教學

1. 在專案資料夾開啟 PowerShell。
2. 建立 GPU 複合模式專用虛擬環境：

```powershell
py -3.11 -m venv .venv-gpu
```

3. 啟用虛擬環境：

```powershell
.\.venv-gpu\Scripts\Activate.ps1
```

4. 安裝相依套件：

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements-gpu.txt
```

第一次啟動時，`rembg` 會依序下載 `isnet-anime` 與約 1 GB 的 `birefnet-portrait` 模型，因此準備時間較長。下載完成後，後續執行會使用本機快取。

`onnxruntime-gpu` 及 CUDA、cuDNN 執行套件的下載容量較大，首次安裝需要較長時間。


## How to Use 如何使用

1. 將待處理圖片放入 `input` 根目錄。
2. 執行：

```powershell
.\.venv-gpu\Scripts\python.exe .\app.py
```

3. 等待畫面上的人物辨識完成；GIF 會顯示 `正在辨識 GIF：12 / 55 個取樣影格` 等進度。
4. 在裁切框內按住滑鼠左鍵拖曳，可移動整個裁切框。
5. 拖曳黃色框線的四邊或四角，可調整裁切範圍。
6. 在倍率欄選擇 50%～200% 的整數；上下按鈕每次增減 10%，也可直接輸入。
7. 確認畫面顯示的輸出尺寸、來源大小與預估輸出大小。預估值不等於重新編碼後的實際檔案大小。
8. 按下「確認裁切與縮放」，將結果以原檔名儲存至 `output`。
9. 完成目前圖片後，程式會自動顯示下一張，倍率會重設為 100%，直到全部處理完畢。

> [!WARNING]
> 若 `output` 已有同名檔案，程式會詢問是否覆寫。選擇不覆寫時會停留在目前圖片，讓你繼續調整或稍後再次確認。

## GPU Acceleration GPU 模式

程式啟動後會在背景依序準備主要模型與二次辨識模型，第一張待處理圖片會等主要辨識裝置準備完成才開始。介面會持續顯示目前狀態：

- `辨識裝置：本機 GPU（CUDA）｜二次辨識：可用`
- `辨識裝置：本機 GPU（CUDA）｜二次辨識：不可用`

主要 CUDA session 建立失敗時，程式會顯示 `GPU 無法使用，程式無法啟動人物辨識` 並關閉，不會改用 CPU。二次辨識模型若在啟動時無法建立，主要辨識仍可繼續，介面會明確顯示二次辨識不可用。

主要模型在執行期間發生 CUDA 錯誤時，目前圖片會列為未處理，程式只重建主要模型一次；重建失敗便停止批次。二次模型發生 CUDA 錯誤時，目前靜態圖片會回退整張圖供手動調整，程式只在背景重建二次模型一次；重建失敗後，本次執行會停用二次辨識。兩個模型都不會改用 CPU 重跑整張圖片，也不會混合兩次辨識結果。

## Animated GIF 動畫 GIF

GIF 的每個取樣影格會先依動畫 disposal 規則合成為完整畫面，再將透明區域暫時合成至中性灰色背景進行人物辨識。透明背景只在辨識時暫時處理，不會改變輸出 GIF。GIF（包含只有一格的 GIF）只使用主要模型，不會觸發二次辨識。

取樣順序為第 1、6、11…格，且一定包含最後一格。程式會先聯集所有有效人物範圍，最後再於整體外框增加設定的留白，形成套用於所有影格的共用裁切框。程式不會排除跨影格的離群辨識結果，因此建議裁切框只會維持或擴大，避免動畫中的姿勢被裁掉。

所有取樣影格辨識完成後才會開始動畫預覽。預覽不提供播放或暫停按鈕，會持續循環播放；若來源影格時間低於 20 ms，預覽以 20 ms 顯示，但輸出仍保留原始時間。

若部分取樣影格辨識失敗，只要仍有有效人物範圍，程式會顯示警告並讓你透過動畫預覽確認。若所有取樣影格都正常完成但沒有可靠結果，初始裁切框會使用整張 GIF；若沒有有效結果且曾發生模型錯誤，整個 GIF 會列為未處理圖片。

確認裁切與縮放後，程式會將共用裁切框及相同輸出倍率套用於所有影格，再逐格建立暫存 GIF。儲存期間會顯示進度並停用其他操作。暫存檔必須能完整解碼，且影格數、縮放後畫布尺寸、播放時間、循環及 disposal 均符合來源，才會取代 `output` 中的正式檔案。

> [!NOTE]
> GIF 需要進行多次人物辨識與逐格重新編碼，處理時間會明顯長於靜態圖片。放大至 200% 時像素數約為 100% 的四倍。重新編碼也可能改變調色盤、壓縮方式及檔案大小，但不會主動降低色彩上限、刪除影格或改變播放速度。

## Folder Structure 資料夾結構

```text
image-cropper/
├── input/                 # 待處理圖片
├── output/                # 已輸出圖片
├── image_cropper/         # 程式核心與介面
├── app.py                 # 程式進入點
├── requirements-gpu.txt   # 複合模式 Python 相依套件
└── README.md
```

程式只讀取 `input` 根目錄，不會遞迴掃描子資料夾，也不會移動或刪除待處理圖片。

## Configuration 設定說明

可在 `image_cropper/config.py` 調整下列參數，重新啟動程式後生效。

### 模型與遮罩門檻

| 參數 | 預設值 | 說明 |
|---|---:|---|
| `DETECTION_MODEL` | `isnet-anime` | `rembg` 使用的人物辨識模型。 |
| `SECONDARY_DETECTION_MODEL` | `birefnet-portrait` | 靜態圖片第一次結果不可靠時使用的二次辨識模型。 |
| `UNRELIABLE_CROP_AREA_RATIO` | `0.95` | 未加留白的建議裁切框達全圖 95% 時觸發二次辨識。 |
| `MASK_LOW_THRESHOLD` | `8` | 暗場人物遮罩門檻。 |
| `MASK_THRESHOLD` | `32` | 一般人物遮罩門檻。 |
| `MASK_HIGH_THRESHOLD` | `96` | 近距離人物遮罩門檻。 |
| `DARK_MASK_MEAN_MAX` | `4.0` | 遮罩平均亮度低於此值時使用低門檻。 |
| `CLOSEUP_MASK_MEAN_MIN` | `40.0` | 遮罩平均亮度達此值時使用高門檻。 |

### 區域過濾與裁切框

| 參數 | 預設值 | 說明 |
|---|---:|---|
| `MIN_COMPONENT_RELATIVE_AREA` | `0.05` | 區域至少須達最大區域的 5%，否則視為雜點。 |
| `MIN_COMPONENT_AREA_RATIO` | `0.0002` | 區域至少須占整張圖片的 0.02%。 |
| `COMPONENT_JOIN_DISTANCE_RATIO` | `0.03` | 相距在圖片長邊 3% 內的遮罩碎片視為同一人物群組。 |
| `SMALL_BORDER_COMPONENT_MAX_AREA_RATIO` | `0.01` | 接觸邊界且小於圖片 1% 的區域視為邊界雜點。 |
| `MIN_FOREGROUND_AREA_RATIO` | `0.01` | 有效人物遮罩至少須占圖片 1%，否則不採用辨識結果。 |
| `DETECTION_PADDING_RATIO` | `0.03` | 建議裁切框在人物外框的各邊增加 3% 留白。 |

### 顯示

| 參數 | 預設值 | 說明 |
|---|---:|---|
| `OUTSIDE_SHADE_ALPHA` | `128` | 裁切框外黑色遮罩透明度；範圍為 0～255，數值越大越暗。 |
